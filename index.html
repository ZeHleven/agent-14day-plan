C1 Agent 本质 vs API / Workflow

面试鸭公开摘要：Agent 有工具、记忆、循环决策直至任务完成。
（摘自题目：（OpenClaw前置）什么是 AI Agent？与直接调 API 的本质区别）

答案要点（整理补充，非面试鸭原文）

  • 单次 API 无状态、无外部动作闭环
  • Agent：感知→规划→行动→观察→再决策
  • Workflow：开发者写死状态转移
  • Harness：Context 装配、权限、沙箱、恢复、Eval、可观测
  • 固定流程/强合规/成本敏感 → 不用 Agent
  • 别把「会调 LangChain」说成会做 Agent 工程

C2 ReAct / Planning / Agent Loop

面试鸭公开摘要：最大步数、状态追踪、超时、兜底退出（摘要级）。
（摘自题目：Agent 死循环问题如何解决（场景题））

答案要点（整理补充，非面试鸭原文）

  • Thought → Action → Observation
  • 终止：Terminate、max steps、timeout、budget、目标判定
  • Plan-and-Execute：可审核，但需重规划
  • 死循环信号：重复动作、状态不变、里程碑不推进
  • 熔断 → Replan / HITL
  • 工具失败先判断可重试还是改计划

C6 RAG 全链路

什么是 LangChain 中的 Agent？它和 Chain 有什么区别？

面试鸭公开摘要：Chain 固定 A→B→C；Agent 动态选工具、观察后再决策。

答案要点（整理补充，非面试鸭原文）

  • Chain：开发者写死的固定流水线（A→B→C），每步顺序确定
  • Agent：由 LLM 动态决定调用哪个工具、以什么顺序
  • Agent 循环：思考→调工具→观察结果→再决策，直到完成
  • Chain 适合流程固定、可预测的任务；Agent 适合需要动态决策的多步任务
  • 代价：Agent 更灵活，但成本、延迟和不确定性更高，需要终止条件与预算
  • 面试加分：说清项目里哪一步必须动态决策

解释 LangChain 中 Chain 和 Agent 概念及应用场景（VIP）

面试鸭公开摘要：面试鸭公开摘要暂无

答案要点（整理补充，非面试鸭原文）

  • Chain：固定流水线，如 Prompt→LLM→解析，适合摘要、翻译、固定问答
  • Agent：动态选工具与顺序，适合搜索+计算+调用系统的多步任务
  • 选择依据：路径是否固定、是否需要外部动作闭环
  • Agent 必须配终止条件：Terminate、max steps、budget
  • 可组合：Agent 内部的子步骤用 Chain 实现

什么是 RAG？在 LangChain 中如何实现？

面试鸭公开摘要：答前先检索知识库，资料+问题一并给模型；LangChain：Load → Split → Embed/入库 → Retrieve → Generate。

答案要点（整理补充，非面试鸭原文）

  • RAG：先检索外部知识，再把证据和问题一起交给模型生成
  • Index：Load → Split（结构优先 + overlap）→ Embed → 向量库 + 元数据
  • Retrieve：向量 + BM25 混合 → RRF 融合 → Rerank
  • 可加 Query Rewrite / Multi-Query / HyDE 提升召回
  • Generate：要求基于证据回答并给出引用
  • 评估：Context Precision/Recall、Faithfulness、Answer Relevancy

用 LangChain 构建文档问答系统的关键组件与步骤（VIP）

面试鸭公开摘要：索引阶段 Loader + Text Splitter（常 500–1000 token）+ 向量库；在线检索片段喂 LLM。

答案要点（整理补充，非面试鸭原文）

  • 离线索引：Loader 读文档 → Splitter 切块 → Embedding → 向量库
  • 切块大小与 overlap 用 Recall@K + 下游质量消融确定
  • 在线：Query（可改写）→ 混合检索 → Rerank → Top-K 进 Prompt
  • Prompt 要求只依据证据回答、附引用、证据不足就说不知道
  • 重要片段放头尾，缓解 Lost-in-the-middle
  • 用 golden set 做回归评估

LangChain Memory 作用与常见类型

面试鸭公开摘要：模型无状态 → Buffer 存全历史；过长超窗需摘要类 Memory（摘要被截断）。

答案要点（整理补充，非面试鸭原文）

  • 模型本身无状态，Memory 负责把历史装配进 Context
  • Buffer 类：保存完整历史，简单但容易超窗
  • 窗口类：只保留最近 N 轮
  • 摘要类：把旧历史压缩成摘要，节省 Token
  • 长期记忆：向量库跨会话召回，需要写入门控和 TTL
  • 压缩时不能丢硬约束和权限规则

（OpenClaw前置）短期记忆 vs 长期记忆

面试鸭公开摘要：面试鸭公开摘要暂无

答案要点（整理补充，非面试鸭原文）

  • 短期：当前窗口内的对话和近 N 步轨迹

MCP 与 Function Calling 的区别

面试鸭公开摘要：面试鸭公开摘要暂无

答案要点（整理补充，非面试鸭原文）

  • Function Calling：模型侧输出结构化调用的接口形态
  • MCP：工具/资源/提示的发现与通信协议，解决互操作
  • FC 回答「模型怎么表达要调什么」；MCP 回答「工具怎么被发现和接入」
  • MCP 常见传输：STDIO / SSE
  • MCP 不是业务流程本身，执行、权限仍在宿主
  • 加分：讲真实接入时的鉴权、超时和错误回传
